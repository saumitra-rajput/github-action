CI / CD Pipeline  — GitHub Actions
0
Self-Hosted Runner Setup One-time
Registered a GitHub Actions self-hosted runner on a Linux machine. Installed Docker, added the runner user to the docker group via usermod -aG docker $USER, and verified socket permissions so the runner can call Docker without sudo.
1
Build Docker Image & Push to Docker Hub Action 1
On every push to main, the first workflow checks out the repo, builds the Docker image from the Dockerfile at the project root, and pushes it to Docker Hub with two tags — latest and the short commit SHA (e.g. abc1234) for traceability. Uses docker/login-action and docker/build-push-action.
2
Copy Code to Runner Action 2
The second workflow (triggered after Action 1 succeeds) uses actions/checkout to copy the latest source onto the self-hosted runner's workspace, making docker-compose.yml and any config files available for the deploy step.
3
Docker Login on Runner Action 2
The runner authenticates to Docker Hub using credentials stored as GitHub Secrets (DOCKER_USERNAME & DOCKER_PASSWORD), so it can pull the freshly-pushed image in the next step without hitting rate limits.
4
Redeploy with docker-compose Deploy
Runs docker-compose down to stop and remove the running containers, then docker-compose up --build -d to pull the latest image and bring the stack back up in detached mode. Zero manual SSH required — every push to main ships automatically to the server.
